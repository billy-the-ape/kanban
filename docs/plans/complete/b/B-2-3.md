## Settled decisions

- All outputs are **estimates** (per B-2.md acceptance: "Label approximate estimates as estimates") — say so in JSDoc and test names.
- Token estimation: reuse the SDK estimator if it is exported from the public `@clinebot/core` entry (check `dist/index.d.ts` for `estimateTokens` / `createTokenEstimator` from `extensions/context/compaction-shared.d.ts`). If not exported publicly, use a documented chars/4 fallback locally and record the gap; do not import from deep `dist/` paths.
- **No double-counted reserves**: if the SDK `reserveTokens` (B-2-4) is set to cover expected output, the trigger computation must not subtract expected output a second time. Single source of truth: the SDK reserve. Document the rule in the module header.

## Implementation

1. New `src/cline-sdk/cline-context-budget.ts`:
   - `estimateRequestTokens({ systemPrompt: string; toolSchemasJson: string; messages: ClineSdkPersistedMessage[]; estimateMessageTokens }): number` — system text + serialized tool schema JSON + message estimates. (Messages type from `./sdk-runtime-boundary`.)
   - `computeContextBudget({ limitTokens, requestTokens, expectedNextInputTokens, expectedOutputTokens, safetyMarginTokens, sdkReserveTokens }): ContextBudget` where `ContextBudget = { inputBudgetTokens, headroomTokens, utilizationRatio, fits: boolean }`.
   - `inputBudgetTokens = limitTokens - sdkReserveTokens - safetyMarginTokens` (the SDK reserve already covers expected output — see double-count rule; expose `expectedOutputTokens` only for reporting, not double subtraction).
   - `utilizationRatio = requestTokens / inputBudgetTokens`; `fits = requestTokens + expectedNextInputTokens <= inputBudgetTokens`.
2. New `test/runtime/cline-sdk/context-budget.test.ts` covering the B-2.md acceptance inputs at the unit level: missing/mistaken metadata (fallback limit), explicit smaller server limit, output reservation via `sdkReserveTokens`, tool-schema overhead (a ~50 KB schema JSON changes the decision), a single large next tool result (200k chars) flipping `fits`, near-limit history at 0.79 vs 0.81 utilization.

## Scope / non-goals

## Verification

- Double-count rule is enforced by a dedicated test (same reserve, with/without `expectedOutputTokens` → identical `inputBudgetTokens`).
