## Investigation (record findings first — they decide the implementation route)

- SDK already has truncation surfaces: `dist/session/services/message-builder.d.ts` (`truncateToolResultContent`, `truncateMiddle`, `truncateToTotalTextBudget`) and `TOOL_RESULT_CHAR_LIMIT = 2000` / `FILE_CONTENT_CHAR_LIMIT = 2000` (`dist/extensions/context/compaction-shared.d.ts`). Determine: do these apply **at message ingestion** (before the request is assembled) or only **during compaction**?
- Check `StartSessionInput.toolPolicies` and any SDK tool-output config for a supported bound.

## Implementation (route chosen from investigation)

1. **Preferred route** — if the SDK exposes a configuration point (tool policy / provider config / session config): set the bound there from `src/cline-sdk/cline-session-runtime.ts` start input; no Kanban duplicator.
2. **SDK-defect route** — if ingestion is unbounded and no config exists: fix in the SDK (upstream issue per B-2.md policy; B-2 is bug-fix track), consume a released/pinned dependency. Never patch `node_modules` as the durable solution. Until the release lands, an interim Kanban-side bound may be added only if no other card is blocked; record it in the patch ledger as retire-when-SDK-lands.
3. **Artifact references** (Kanban-side, new `src/workspace/task-artifacts.ts`):
   - Store full content under the task workspace, e.g. `<task-workspace>/.kanban/context-artifacts/<toolCallId>-<ts>.txt` (atomic write via the existing `lockedFileSystem` helpers used by `src/state/workspace-state.ts`).
   - The bounded message carries: bounded excerpt (head + tail with an omission marker) + `Full content: <absolute path>` reference so the agent can page it with reads.
   - Artifacts are data, never code: writing them must not touch tracked files (invariant).
4. Wire the excerpt path into whichever tool-result route the investigation selects; keep the tool name/exit metadata intact.

## Verification

- Unit tests `test/runtime/task-artifacts.test.ts`: artifact write/read, path shape, atomicity.
- Integration test with the fake host + fake OpenAI provider: a session reads a ~1 MB file → assert (a) the assistant-facing content is bounded, (b) the artifact file exists with the full content, (c) the reference path is in the message, (d) the next request fits the budget even though prior usage was low.
- `npm test`, typecheck.

## Acceptance

- The large single file read cannot overflow the fake provider's limit; the agent can retrieve the full content via the artifact path.
- Artifacts remain on disk (no cleanup here — deletion safety is B-5's domain).

## Stop conditions

- No ingestion-time hook exists anywhere (Kanban or SDK) → SDK upstream fix is the only durable route; deliver the artifact mechanism + SDK issue, park the bound with evidence. Do not build a second truncator that competes with the SDK's compaction truncation.
- Artifact location collides with the task worktree's git status (must not dirty the delivery tree) → move artifacts outside the repo (e.g. alongside the task state directory) and update the path convention.
