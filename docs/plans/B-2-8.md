## Implementation

1. **Restart path**: `src/cline-sdk/cline-task-session-service.ts` — the restart flow (`lastStartRequestByTaskId` → `restartTaskSession`, see `src/cline-sdk/cline-session-runtime.ts:~291`) must re-resolve (not cache-and-replay a stale) context limit + compaction config from the current launch config. Add the new request fields to the stored start request. Do not conflate with the B-1.7 restart defect ("No previous Cline session config is available") — that is B-1/B-4 territory; this card only guarantees the policy fields survive.
2. **All trpc entry points**: `src/trpc/runtime-api.ts` — `startTaskSession` (~168), `sendTaskSessionInput` (~350), and the home-agent / restart call sites (~428, ~629) all go through the same resolver + `buildClineCompactionConfig`. Grep for `startTaskSession(` to find any remaining bypass.
3. **Summarization coverage**: confirm the compaction summarizer (B-2-4) is the *only* model call outside the main loop that Kanban triggers; grep `src/` for other provider invocations (e.g. title generation) and bring them under the same resolved-limit policy or document them as exempt with a reason.
4. **Single-worker guard**: default worker limit is 1. Find the current concurrency behavior at task start (board `in_progress` handling in `src/commands/task.ts` + `src/trpc/runtime-api.ts`); if nothing prevents two simultaneous Cline sessions against the local provider, add a minimal guard: a second start while a Cline session is active returns an explicit, user-readable error (UI/CLI show the message). Do **not** build queuing or a parallel scheduler — that is B-11.
