## Implementation

1. **Restart path** — done in `src/cline-sdk/cline-session-runtime.ts` (the runtime owns `lastStartRequestByTaskId` and `restartTaskSession`, so re-resolution lives there; the service and the test harness only wire the resolver):
   - New `ClineLaunchConfigResolver` type + `resolveClineLaunchConfig` runtime option (and `CreateInMemoryClineTaskSessionServiceOptions.resolveClineLaunchConfig`, forwarded by `src/server/runtime-server.ts` to `createClineProviderService().resolveLaunchConfig`).
   - `restartTaskSession` now calls `resolveRestartedLaunchPolicy()`: re-resolves credentials (OAuth refresh), context limit + source, and rebuilds the compaction config via `buildClineCompactionConfig` from the CURRENT launch config. Provider/model are pinned to the saved request (`providerIdOverride`/`modelIdOverride`) so the conversation continues with the same model. Without a resolver (unit tests, embedded hosts) the stored snapshot is replayed unchanged.
   - The runtime's B-2.5 calibration then re-derives the calibrated window on the fresh (uncalibrated) config — no double subtraction.
   - The stored start request already carried `contextWindowTokens`, `contextWindowSource`, and the uncalibrated `compaction` (B-2.4/B-2.5); no new fields were needed.
   - Not conflated with the B-1.7 restart defect: "No previous Cline session config is available" is untouched (B-1/B-4 territory).
2. **All trpc entry points** — audited; every session-creating entry point in `src/trpc/runtime-api.ts` already resolved the launch config and passed `buildClineCompactionConfig` (no bypass found):
   - `startTaskSession` handler (board start; CLI `kanban task start` goes through the same endpoint).
   - `sendTaskChatMessage` handler — home-agent auto-start.
   - `reloadTaskChatSession` handler — home-agent restart.
   - The in-process restart path (follow-ups after the session ends — including the review/repair auto-commit prompt — `service.reloadTaskSession` restarts, and the context-overflow recovery restart) now re-resolves via the runtime resolver above.
3. **Summarization coverage** — confirmed: the B-2.4 compaction summarizer (same provider/model, policy-configured) is the only auxiliary model call Kanban triggers. Other candidate sites are exempt:
   - Task title generation (`src/core/task-title.ts` `resolveTaskTitle`) is deterministic — no model call at all.
   - Compaction `beforeModel` / `afterTool` hooks (B-2.5/B-2.6/B-2.7) are deterministic and model-free.
   - `getProviderModels` / account-balance / OAuth calls are provider API calls, not model completions.
4. **Single-worker guard** — added at the top of `InMemoryClineSessionRuntime.startTaskSession` (`assertSingleActiveClineSession`). At most one live Cline session per workspace runtime. The check is race-free: `startTaskSession` binds the requested session synchronously before its first await, so overlapping starts for distinct tasks can never both pass; a blocked start runs before any state write (no orphaned bindings or start-request snapshots). Same-task starts (replace / resume-from-trash) are unaffected. No queuing/scheduler (B-11).

**Guard error message text:**

> `Another Cline session is already active (task "<taskId>"). Cline sessions run one at a time by default: stop that session before starting this one.`

Surfaces as the task's `warningMessage` + system chat message (`emitTaskFailure`, state `awaiting_review`/`reviewReason: "error"`), shown in the UI task panel and returned as `error` on the tRPC response path; the CLI `kanban task start` surfaces it via the failed response. Recoverable: stop the active session, then (re)start — a start blocked before any session existed needs the task entry cleared first (`/clear` in the task chat, or trash/restore), matching the existing recovery behavior for any failed start.

## Verification

- `test/runtime/cline-sdk/single-worker-and-restart-policy.test.ts` (new, 6 tests, all green):
  - Restart regression: complete one turn → emit `ended` (binding clears, state `awaiting_review`) → follow-up (restart path) → second captured `FakeClineSessionStartConfig` has the identical calibrated `compaction` config as the first, and the resolver was called pinned to the saved provider/model.
  - Re-resolution (not cache-and-replay): with the launch config changed between turns (larger context override, rotated key), the restart's SDK start carries the fresh window and credentials.
  - Unresolvable restart: explicit user-readable error + no orphaned start; recoverable once the provider resolves again.
  - Concurrency (sequential): second `startTaskSession` while a session is active → guard message naming the blocking task; exactly one SDK session created; winner unaffected; recoverable after stop.
  - Concurrency (overlapping): two simultaneous starts → exactly one session started, exactly one explicit guard failure; recoverable for the loser.
  - Review/repair prompt path: auto-commit prompt (`"Handle this commit action using the provided git context."`, the default template from `web-ui/src/git-actions/build-task-git-action-prompt.ts` used by `use-review-auto-actions.ts`) sent while another session is active → explicit guard failure; after stopping the active session the same prompt lands in a restarted session carrying the same compaction policy.
- `test/runtime/trpc/runtime-api.test.ts`: per-entry-point compaction assertions — board `startTaskSession` (full deep-equal against `buildClineCompactionConfig`), home-agent auto-start via `sendTaskChatMessage` (provider-bound summarizer), home-agent reload restart (pre-existing, full deep-equal).
- `npm test` (full suite green), `npm run typecheck` (clean).
