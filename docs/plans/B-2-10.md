## Measurements

Tested against the pinned @clinebot/core 0.0.38 with the fake OpenAI-compatible
provider (`test/utilities/fake-openai-provider.ts`, its own chars/4 tokenizer and
exact overflow error shapes). All token values are **estimates** (B-2.3 chars/4
fallback estimator); the suite asserts and logs them as such.

| Measurement (all estimates) | Value |
| --- | --- |
| Tested effective budget (all e2e scenarios) | 8,000 tokens, source `override` (the S2 explicit smaller limit; the session-start log records `contextLimitSource: "override"`), plus the documented 200,000-token fallback and the override/metadata precedence rules at the provider-service level |
| Calibration at the 8k budget | system prompt 16 + tool schemas 1,298 + safety margin 4,096 → calibrated window 6,686; reserve 4,596 = 500 (output) + 4,096 (margin), single-counted; message trigger 2,090 |
| Assembled request size, post-B-2, 12-round near-limit session | max 3,252 prompt tokens (provider accounting incl. tool schemas); 3,752 with the 500 output reserve → 46.9% utilization; zero overflow rejections; the beforeModel hook fired on 9 of 12 requests |
| Assembled request size, pre-B-2 (same fixture, un-compacted) | 10,992 message tokens by round 12 (37% over the 8k window before any output) |
| Output reservation | 500 tokens (provider max output) reserved exactly once across build → calibrate → hook; every provider request satisfied `prompt + 500 ≤ 8,000` |
| Tool-schema overhead (S4) | a ~1,527-token schema moves the calibrated trigger down by exactly its estimated size (2,090 → 564); the same 3,000-token history fits without the schema and compacts with it |
| Large next tool result (S5) | 806,727-char run_commands result bounded to 4,000 chars (10% of 8k = 3,200 chars → 4,000 floor); follow-up request 2,328 prompt tokens (≈201,682 unbounded); full output preserved as an 814,855-char local artifact; zero overflow |
| Near-limit history (S6) | 0.79 utilization (7,900/10,000 with 500 reserve + 1,500 margin) → no compaction; 0.81 (8,100/10,000) → compaction, rewritten request + reserve ≤ limit − margin; 12-round e2e: zero provider overflow errors |
| Summarizer request size | 0 — local mode uses the deterministic compactor (request-scoped rewrite); exactly one provider request per user round (12/12), no summarizer model calls |

Note on the 80% trigger (B-2.4): with the default computed margin the trigger sits
at `limit − output − max(4,096, 10%)`, so small windows trigger earlier (42.6% of
8k); the 80% point is reached when the user-tuned margin (B-2.9) is small relative
to the window, which S6's 0.79/0.81 matrix exercises directly.
