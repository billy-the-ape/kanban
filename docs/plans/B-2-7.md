## Settled decisions

- Command-output excerpt shape: first N lines + last M lines (default N = M = 100, revisit with measurements) + `... [truncated K lines; full output: <artifact path>]`.
- **Exit status is never truncated away** — later milestones (B-7 deterministic verification) rely on exit status; keep it in the message head.
- Diff results: same mechanism; for large diffs keep per-file stat summary + bounded hunks + artifact path.
- Reuse B-2-6's `src/workspace/task-artifacts.ts`; do not introduce a second artifact store.

## Implementation

1. Apply the B-2-6 route (SDK config/tool policy vs SDK upstream fix) to the terminal tool output path; verify with the installed SDK types + runtime behavior (types alone do not prove it).
2. Apply the same to diff-producing tool results (the Cline loop's diff/git tools as exposed through the SDK host); if the SDK treats them as plain tool results, the B-2-6 tool-result bound may already cover them — prove it with a test rather than assuming.
3. Tests:
   - `test/runtime/cline-sdk/tool-output-bounds.test.ts`: a command printing ~500 KB / 100k lines → message bounded, exit code present, artifact contains full output; a clean (exit 0) and a failing (exit 1) command both keep their exit status in the bounded message.
   - Large-diff case: `git diff` over a large staged change in a scratch worktree → bounded + artifact + per-file summary.
4. `npm test`, typecheck.

## Verification

- Fake-provider integration: a session that runs one very verbose command stays within the provider token limit; the agent reads the artifact path to retrieve the tail of the output.

## Acceptance

- No single command output or diff can overflow the budget, even after a low-usage prefix.
- Exit status and tool identity are always visible in the bounded message.

## Deployment

None.

## Handoff

Changed files, measured excerpt sizes, SDK route confirmation for terminal output, SDK issue link if opened.

## Stop conditions

- Same as B-2-6: if no ingestion-time hook exists, the durable fix is the SDK (upstream issue + pinned release); deliver artifact wiring + evidence, park the remainder.
- Bounding must alter the command (e.g. shell-level `| head`) to work → reject that route; it changes what executed and corrupts delivery evidence. Bounding must be on the **result text**, not the command.
