## Settled decisions

- Storage: Kanban's own settings state — `RuntimeConfigState` (`src/config/runtime-config.ts`), the existing global/project config path — **not** the SDK provider settings (the SDK schema strips unknown fields; only `contextWindow` exists there).
- Precedence (extends B-2-2): `RuntimeConfigState` override **>** SDK provider-settings `contextWindow` override **>** provider metadata **>** fallback. Record this decision in the handoff; if B-2.md reviewers disagree, the min-rule in the resolver still keeps the effective limit safe.
- Field names follow the SDK schema where names exist (`strategy`, `thresholdRatio`-style, reserve tokens); final names decided against `CoreCompactionConfig` (`dist/types/config.d.ts:61`).

## Implementation

1. `src/config/runtime-config.ts` — extend `RuntimeConfigState` (~line 26) with an optional `contextBudget` object:
   `{ contextWindowOverrideTokens?: number | null; compactionStrategy?: "basic" | "agentic"; triggerThresholdRatio?: number; outputReserveTokens?: number; safetyMarginTokens?: number }`
   - Load: defaults from B-2-4/5 values; unknown/missing → defaults (no migration, additive).
   - Validate on save: tokens are positive integers (or explicit `null`/absent); `triggerThresholdRatio` in (0, 1]; `compactionStrategy` in the enum. Reject invalid values with a clear error message (B-2.md: "Reject invalid values").
2. `src/core/api-contract.ts` — `runtimeConfigResponseSchema` (~941) and `runtimeConfigSaveRequestSchema` (~961): add the corresponding optional fields; wire through the trpc config get/save handlers in `src/trpc/runtime-api.ts`.
3. `src/cline-sdk/cline-context-policy.ts` / `cline-compaction-config.ts` — resolver + config builder consume the settings (override tier, strategy, threshold, reserve, margin).
4. Web UI (existing paths only): the Cline settings area (`web-ui/src/hooks/use-runtime-settings-cline-controller.tsx` + its shared settings components under `web-ui/src/components/shared/`) — add an "Advanced / Context budget" section with the five fields, plus a read-only line showing the **current effective limit and its source** (from the resolver; this is the "Display the source of the selected limit" requirement from B-2.2).
5. No new cloud credentials, no automatic provider fallback (explicit B-2.md constraint).

## Verification

- Schema/unit tests: invalid values rejected (ratio 0, ratio 1.2, negative tokens, non-integer tokens, bad strategy enum); valid values round-trip save → load; missing fields load as defaults.
- Harness test: set `contextWindowOverrideTokens` smaller than the served limit → session-start diagnostic log (B-2-0) shows the override value + source `override`.
- Web UI test: settings controller round-trips the section (extend `use-runtime-settings-cline-controller.test.tsx`).
- `npm test`, typecheck.

## Acceptance

- An operator can cap a local model below its reported limit purely from the UI; defaults (unset) reproduce B-2-4/5 behavior exactly.
- The effective limit + source is visible in settings and in the session-start log.
