## Settled decisions

- Storage: Kanban's own settings state — `RuntimeConfigState` (`src/config/runtime-config.ts`), the existing global/project config path — **not** the SDK provider settings (the SDK schema strips unknown fields; only `contextWindow` exists there).
- Precedence (extends B-2-2): `RuntimeConfigState` override **>** SDK provider-settings `contextWindow` override **>** provider metadata **>** fallback. Record this decision in the handoff; if B-2.md reviewers disagree, the min-rule in the resolver still keeps the effective limit safe.
- Field names follow the SDK schema where names exist (`strategy`, `thresholdRatio`-style, reserve tokens); final names decided against `CoreCompactionConfig` (`dist/types/config.d.ts:61`).

### Final field names

| UI / config / API field | SDK / resolver mapping | Default when unset |
| --- | --- | --- |
| `contextWindowOverrideTokens` | tier-0 override in `resolveLaunchConfig` (source `"override"`) | B-2-2 resolution (provider-settings → metadata → 200k fallback) |
| `compactionStrategy` | `CoreCompactionConfig.strategy` | `"basic"` |
| `triggerThresholdRatio` | `CoreCompactionConfig.thresholdRatio` | 0.8 (`CLINE_COMPACTION_THRESHOLD_RATIO`) |
| `outputReserveTokens` | `CoreCompactionConfig.reserveTokens` | model `maxTokens`, else 16,384 |
| `safetyMarginTokens` | no SDK field — calibration + beforeModel hook | max(4,096, 10% of limit) |

Save semantics: `null` clears a field to its default; `undefined` leaves the
stored value untouched. Same rule for the whole `contextBudget` object.

### Precedence (settled, recorded per plan)

`contextWindowOverrideTokens` (tier 0) **>** SDK provider-settings
`contextWindow` override **>** provider metadata **>** documented 200k
fallback. The tier-0 override wins outright (not min-reconciled); if reviewers
disagree, the B-2-2 min-rule still bounds the effective limit.

### UI location

Settings dialog → Cline agent section → "Context budget" subsection (below
Model, above MCP servers), visible when the Cline agent is selected. Shows a
read-only "Effective context window: N tokens (override | provider metadata |
fallback default)" line from the config response.

### Validation rules

| Field | Rule | Error message |
| --- | --- | --- |
| `contextWindowOverrideTokens` | positive integer | `contextWindowOverrideTokens must be a positive integer token count.` |
| `outputReserveTokens` | positive integer | `outputReserveTokens must be a positive integer token count.` |
| `safetyMarginTokens` | positive integer | `safetyMarginTokens must be a positive integer token count.` |
| `triggerThresholdRatio` | number in (0, 1] | `triggerThresholdRatio must be a number between 0 and 1 (exclusive of 0).` |
| `compactionStrategy` | `"basic"` \| `"agentic"` | `compactionStrategy must be either 'basic' or 'agentic'.` |

Enforced at the API boundary (zod, `runtimeContextBudgetSaveSchema`) and as
defense in depth in `validateContextBudget`; corrupted stored fields degrade
to defaults on load instead of failing.
